德州扑克（Texas Hold'em）作为全球竞技深度最强、商业变现与流动性极高的棋牌品类，线上产品正向“极速娱乐化”、“社群私局化”与“Web3 可信透明”三大维度演化。本专案旨在打造一套高并发、低延迟、深度还原专业竞技同时具备高留存特色玩法的综合系统，支持 B 端商户包网接入与 C 端跨端体验。

SEC 03 核心玩法规则与牌局生命周期 (Gameplay & Lifecycle)

3.1 桌位结构与行动顺位

标准德州扑克支持 2 人（单挑 Heads-Up）、6 人（6-Max，核心推荐）与 9 人（满员桌 Full-Ring）。

  • BTN (Button / 庄家位)：翻前倒数第 3 位行动（若无 Straddle）；翻后所有轮次最后行动（核心位置优势）。
  • SB (Small Blind / 小盲位)：强制投入指定小盲注（如 $0.5\times BB$），翻后第一行动顺位。
  • BB (Big Blind / 大盲位)：强制投入大盲注（$1\times BB$），翻前拥有最终 Option（选择权）。
  • UTG (Under The Gun / 枪口位)：翻前第一行动顺位。
⚠️ 单挑桌 (Heads-Up) 特例规则（研发与测试极易出错的 P0 分支）：
当桌上仅剩 2 位玩家 时，规则发生重大反转：
1. BTN 兼任 SB：同一玩家同时担任庄家与小盲位。
2. 翻前首位行动：BTN/SB 先行表态，BB 最后行动（持 Option）。
3. 翻后首位行动：BB 先行表态，BTN/SB 持位置优势最后行动。
注：与多人桌 BTN 全程最后说话形成反差，必须独立编写分支状态机！

4.2 多重主池与边池动态拆分核心算法

当多名筹码不同的玩家发生 All-in 时，系统根据每位玩家的总投入贡献，按阶梯切分为主池（Main Pot）与多个边池（Side Pots 1..N）：

// 生产级主边池拆分算法（含相邻底池合并）
function calculatePots(playersContribution) {
  let pots = [];
  let active = playersContribution.filter(p => p.amount > 0);

  while (active.length > 0) {
    // 以当前未结算筹码中的最小下注值为本层切分基准
    let minBet = Math.min(...active.map(p => p.amount));
    let currentPotAmount = 0;
    let eligibleContenders = [];

    for (let p of active) {
      currentPotAmount += minBet;
      p.amount -= minBet;
      if (!p.isFolded) eligibleContenders.push(p.id);  // 弃牌者的死钱留在池中但无争夺权
    }

    // ★ 关键：相邻底池若「有权争夺玩家集合」完全相同，必须合并
    //   真实的边池分层只能由存活玩家的 All-in 金额差异产生；
    //   弃牌玩家的死钱会造成额外分层，但不构成独立底池。
    const key = [...eligibleContenders].sort().join("|");
    const last = pots[pots.length - 1];
    if (last && last.key === key) {
      last.amount += currentPotAmount;
    } else {
      pots.push({
        potIndex: pots.length,
        potType: pots.length === 0 ? "Main Pot" : `Side Pot ${pots.length}`,
        amount: currentPotAmount,
        eligiblePlayers: eligibleContenders,
        key
      });
    }

    active = active.filter(p => p.amount > 0);
  }
  return pots;  // 派彩时从最后一个边池向前依序比牌派发
}

// 验收断言（对应 QA_01 TC-POT-003 / TC-POT-004）：
//   1. 任意相邻底池的 eligiblePlayers 集合不得相同
//   2. Σ 底池金额 === Σ 玩家投入总额（含死钱），零误差

SEC 05 抽水模型与商业化结算 (Rake & Monetization)

5.1 核心三大抽水准则

  1. No Flop No Drop（未见翻牌不抽水）：行业铁律。若牌局在翻牌圈前结束（如翻前全员弃牌给盲注），平台一律不抽取任何抽水，保护激进翻前打法，确保桌台周转。
  2. 未跟注筹码先行剔除 (Uncalled Bet Deduction)：超额下注且无对手跟注的筹码，属于从未发生争夺的死筹，先行退回原玩家，不计入抽水基数。
  3. 向下取整至最小货币单位 (Rounding Floor)：抽水一律向下取整（如保留至 1 分），舍入误差让利给玩家，严禁向上取整导致暗抽合规风险。

5.2 费率与封顶阶梯矩阵 (Cap Ladder)

SEC 06 特色创新机制需求 (RIT & EV Cashout)

6.1 发多次牌机制 (Run It Twice / Multi-Times)

当至少 2 名玩家 All-in 且下注轮锁定后，系统弹出 5 秒确认框。全体同意后，剩余公牌连续发 2 次（或 3 次），底池按次数均分独立比牌结算。

★ 销牌一致性铁律：发多次牌必须使用同一副牌的剩余牌堆（严禁重新洗牌），且每一次发牌轮次必须严格销一张牌（Burn Card）。若跳过销牌将破坏 RNG 序列的可验证性。

6.2 全下 EV 保险折现 (EV Cashout)

图 6-1：EV Cashout 业务决策流
多人 All-in 锁定底池 ➔ 同时校验：胜率 Pwin ≥ 60% 且 该底池 ≥ 20 × BB
分支 A：胜率 ≥ 60% 触发折现

1. 弹出 5 秒倒计时折现选择框
2. 扣除 1% 平台服务手续费
3. 折现筹码立即打入玩家余额入袋为安
4. 玩家退出底池争夺，底池后续胜负由平台资金池接管

分支 B：未达到门槛 / 玩家拒绝

1. 两项门槛任一不达标即不唤起面板
2. 玩家点击拒绝或 5 秒超时
3. 正常打完剩余发牌流程
4. 依最终公共牌摊牌比牌，胜者全拿，负者出局

数学公式（含平手率）：

Raw_EV        = TotalPot × P_win  +  (TotalPot ÷ 2) × P_tie
Cashout_Payout = Raw_EV × (1 − FeeRate)      // FeeRate 默认 1.0%，后台可配置
★ 对手知情权边界：折现面板仅对触发玩家可见，对手端无任何提示（含动效与时序差异）。若告知对手「对方已折现」，等同泄露其牌力领先，构成不对等信息优势。对手若最终获胜，仍获得完整底池，差额由平台承担。
⚠️ 费用不重复原则：已被折现的部分不再计入抽水基数；未折现的剩余底池照常抽水。任何一局须满足 折现手续费基数 + 抽水基数 ≤ 底池总额。

SEC 07 可证明公平 RNG 技术架构 (Provably Fair)

为消除线上扑克“后台控牌、杀大赔小”的信任痛点，系统采用密码学可证明公平体系：

图 7-1：Provably Fair 发牌与验牌全时序流程
1
开局前哈希承诺：服务端生成高强度的随机 Server Seed，并将其 SHA-256 哈希值广播给桌上玩家（明文严格保密，哈希防篡改）。
2
多方种子加盐：收集桌上存活玩家上报的客户端随机种子 Client Seeds 与本局全局自增 Nonce。
3
洗牌算法执行：服务端计算 HMAC_SHA256(ServerSeed, ClientSeeds + Nonce)，以此哈希流驱动 Fisher-Yates 确定性洗牌。
4
拒绝采样消除模偏差（Modulo Bias）：32 位随机数空间 $2^{32}$ 无法被牌堆区间长度整除时，直接取模会使前若干个索引的中选概率偏高（52 张牌时 $2^{32} \bmod 52 = 48$，索引 0~47 比 48~51 高约 $1.2\times10^{-8}$）。单局偏差极微，但在日均千万手牌规模下可被卡方检验统计显著检出，一旦被审计揭露，「可证明公平」的品牌承诺即告破产。
解法：将哈希流截断至 $\lfloor 2^{32}/bound \rfloor \times bound$，落在区间外的随机数直接丢弃并取下一个。丢弃与重取过程完全由哈希流决定，验证方可完整复现，不破坏验证链；期望重试次数趋近于 0。
5
局后公开验牌：牌局结算完成后，系统公开明文 Server Seed。玩家可在前端输入种子即时重算验证牌堆序列，100% 杜绝换牌！
